## O que é programar

Um programa é uma **sequência de instruções** que o computador executa na ordem em que estão escritas. Não há mágica nem inteligência nisso: ele faz exatamente o que está no papel, inclusive quando o que está no papel é bobagem.

Três ideias cobrem quase tudo o que você vai ver nos notebooks do curso:

- **Variável** — um nome que guarda um valor. `preco = 250` quer dizer "a partir de agora, `preco` vale 250". O sinal de igual aqui não é o da matemática: ele não afirma uma igualdade, ele **atribui**. Por isso `x = x + 1` faz sentido em código e não faria numa equação.
- **Função** — um trecho de código com nome, que recebe entradas e devolve uma saída. `media([2, 4, 6])` devolve `4`. Você usa dezenas de funções que outra pessoa escreveu, e é isso que torna o trabalho viável.
- **Repetição** — mandar o computador fazer a mesma coisa muitas vezes. É daí que vem o poder: treinar um modelo é repetir uma correção milhares de vezes, e a máquina não se cansa nem erra a conta.

<Caixa tipo="erro">
Achar que precisa **decorar** a sintaxe. Ninguém decora — nem quem programa há dez anos. O que se aprende é o **repertório**: saber que existe uma forma de fazer aquilo e saber procurar como. Errar a vírgula e o computador reclamar não é sinal de que você não leva jeito; é o funcionamento normal da coisa, todo dia, para todo mundo.
</Caixa>

## Python: o que aparece nas aulas

Python é a linguagem do curso, e a escolha não é gosto: praticamente todo o ecossistema de machine learning é escrito nela. O que você vai encontrar nos notebooks cabe em pouca coisa.

**Listas** guardam vários valores em ordem, e a contagem começa no **zero** — o primeiro item é o item `0`. É a fonte de metade dos erros de quem está começando.

```python
precos = [250, 310, 180]
precos[0]        # 250, o primeiro
len(precos)      # 3, quantos itens tem
```

**Laços** repetem um bloco para cada item:

```python
for p in precos:
    print(p * 2)
```

**Funções** empacotam uma tarefa com nome:

```python
def dobro(x):
    return x * 2

dobro(21)        # 42
```

E **bibliotecas** são código pronto que você importa. `import numpy as np` quer dizer "traga o NumPy e me deixe chamá-lo de `np`". Você vai ver `np` em todo notebook do semestre.

## NumPy: por que ele existe

Uma lista comum do Python é flexível e lenta. O **NumPy** troca a flexibilidade por velocidade: ele guarda os números todos do mesmo tipo, lado a lado na memória, e opera neles em bloco. Essa estrutura se chama **array**.

A diferença prática é enorme na escrita. Sem NumPy, dobrar mil números pede um laço; com NumPy, é uma linha:

```python
import numpy as np

precos = np.array([250, 310, 180])
precos * 2           # array([500, 620, 360]) — multiplicou todos de uma vez
precos.mean()        # 246.67
precos > 200         # array([True, True, False])
```

Escrever a operação para o array **inteiro**, sem laço, se chama **vetorização**. **Aperte "rodar os dois"** e compare os caminhos:

<VizEmbed titulo="o mesmo trabalho, dois caminhos">
  <Vetorizacao />
</VizEmbed>

Repare no que muda quando você aumenta o tamanho: o número de voltas do laço explode e **o código do NumPy continua o mesmo**. Além de mais curto de escrever, ele é dezenas de vezes mais rápido, porque a conta acontece em código otimizado por baixo em vez de rodar linha a linha no Python.

O outro conceito que vale trazer é o **formato** (_shape_) de um array: quantas linhas e colunas ele tem. Uma imagem de 28×28 pixels é um array de formato `(28, 28)`; mil imagens dessas viram `(1000, 28, 28)`. Quase todo erro que você vai ver rodando notebook de ML é um erro de formato — dois arrays que não batem —, e ler a mensagem com calma resolve a maior parte deles.

## A matemática que o curso usa

Menos do que parece, e sempre com um significado concreto por trás. Quatro coisas.

**Probabilidade** é o quanto se acredita em algo, entre 0 e 1. Vai aparecer na Aula 3, quando o modelo deixar de responder "é spam" e passar a responder "82% de chance de ser spam".

**Média** é o valor típico: some tudo e divida pela quantidade. Ela resume um conjunto num número — e esconde a variação dentro dele. **Desvio padrão** é justamente o quanto os valores costumam se afastar dessa média.

Duas turmas podem ter a **mesma média** e realidades completamente diferentes. **Arraste as bolinhas** e depois compare as duas turmas:

</VizEmbed>

É por isso que os dois andam juntos: a média sozinha diria que as duas turmas foram iguais. Isso volta na Aula 2, quando o curso for **padronizar** as features — a conta ali é exatamente "subtraia a média e divida pelo desvio".

**Inclinação** é a última, e é a que costuma assustar. Ela responde: *se eu andar um pouquinho para a direita, o que acontece com a altura?* Se sobe, a inclinação é positiva; se desce, negativa; se não muda, é zero. **Arraste o ponto** pela curva:

Guarde a última observação: **onde a inclinação é zero, você está no fundo.** Toda a Aula 1 é sobre isso — treinar um modelo é procurar o ponto mais baixo de uma curva de erro, e a inclinação é a bússola que diz para que lado andar. Quando aparecer a palavra **derivada**, ela quer dizer exatamente "a inclinação naquele ponto".

## Git e GitHub: para que servem

Git é o programa que guarda o **histórico** do seu código: cada versão salva fica registrada, com quem mudou o quê e quando, e dá para voltar a qualquer ponto anterior. GitHub é um site que hospeda esses históricos na internet, para várias pessoas trabalharem no mesmo projeto.

Por que isso importa para você agora: os notebooks das aulas ficam num repositório, e o jeito de pegá-los é com Git. Quatro palavras cobrem o uso do semestre:

- **repositório** — a pasta do projeto, com todo o histórico dentro.
- **clonar** — baixar uma cópia do repositório para a sua máquina.
- **commit** — salvar um ponto no histórico, com uma mensagem dizendo o que mudou.
- **push** — mandar os seus commits para o GitHub.

O *como* está logo abaixo.

## Montar o ambiente

Meia hora, uma vez só. São quatro peças: **Python**, um **editor**, o **Git** e o **projeto**. Se travar em qualquer passo, traga o erro para a aula — é mais rápido resolver junto do que sozinho.

### 1. Python, com o uv

Não instale o Python direto do site. Use o **uv**, que instala o Python e cuida das bibliotecas de cada projeto sem misturar um com o outro — que é o problema que faz todo mundo perder tarde de trabalho.

No **macOS** ou **Linux**, abra o Terminal e cole:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

No **Windows**, abra o PowerShell e cole:

```powershell
winget install --id=astral-sh.uv -e
```

Feche e reabra o terminal, e confira se funcionou:

```bash
uv --version
```

Se aparecer um número de versão, está pronto. O uv baixa a versão certa do Python sozinho na primeira vez que precisar — você não precisa instalar o Python separadamente.

### 2. O editor: VS Code

Baixe o **Visual Studio Code** em [code.visualstudio.com](https://code.visualstudio.com/). Depois de instalar, abra o painel de extensões (o ícone de blocos na barra lateral) e instale duas:

- **Python**, da Microsoft;
- **Jupyter**, também da Microsoft — é ela que faz o VS Code abrir e rodar notebooks.

### 3. Git

No **macOS**, o jeito mais simples é digitar `git --version` no Terminal: se ele não estiver instalado, o próprio sistema oferece instalar. No **Windows**, baixe em [git-scm.com](https://git-scm.com/downloads) e aceite as opções padrão.

Depois, diga ao Git quem é você — isso vai junto de cada commit:

```bash
git config --global user.name "Seu Nome"
git config --global user.email "seu@email.com"
```

Use o mesmo e-mail da sua conta do GitHub. Se você ainda não tem conta, crie uma em [github.com](https://github.com/) — leva dois minutos e é grátis.

### 4. O projeto e o primeiro notebook

Com o repositório da aula clonado (`git clone <endereço do repositório>`), entre na pasta e prepare o ambiente:

```bash
cd nome-da-pasta
uv sync
```

O `uv sync` lê a lista de bibliotecas do projeto e instala todas numa pasta `.venv` ali dentro, isolada do resto da máquina. Para abrir o notebook, abra a pasta no VS Code (`code .`), clique no arquivo `.ipynb` e, no canto superior direito, escolha o **kernel** — selecione o Python que está em `.venv`. Rode a primeira célula com `Shift + Enter`.

Se preferir o Jupyter no navegador em vez do VS Code:

```bash
uv run --with jupyter jupyter lab
```
